# Loan Calculator — PRD

> 状态：**已冻结（Frozen）**。版本：v1.0。冻结日期：2026-07-16。
> 事实来源：`loan-calculator/shaping/06-最终定型稿.md`（冻结版 v1.0）。
> 待决策事项：`待决策事项.md` 中 DEC-01~12 已全部处理为 Deferred by user，无 Open 项。

## 1. 概述

面向通用大众的免费、无需注册的贷款计算器，纯前端单页应用（无后端、无数据库），托管于 GitHub Pages。用户输入贷款金额、年利率、期限后，可在「固定利率法（Flat/Fixed Interest）」与「递减余额法（Reducing Balance/Amortizing）」两种计算方式间手动切换，查看月供、总利息、总还款额及完整摊还明细表。货币单位为 MYR，界面为英文，不做账号体系与任何持久化。

## 2. 术语与假设

- **固定利率法（Flat/Fixed Interest）**：利息按原始本金与固定年利率计算，总利息在贷款期内均匀分摊到每期月供，月供构成（本金/利息占比）不随期数变化。
- **递减余额法（Reducing Balance / Amortizing）**：利息按每期期初剩余本金计算，月供总额固定，但本金与利息占比逐期变化（本金占比递增，利息占比递减）。
- 所有金额单位为 MYR，展示精度为 2 位小数，舍入规则为「向上取整（round up）」，而非四舍五入（对应冻结定型稿已确认决策 N6）。
- 年利率输入值为百分比数值（如输入 4 表示年利率 4%）。
- 本 PRD 所有需求均以冻结定型稿 v1.0（2026-07-16）为唯一事实来源；未覆盖内容记录于 `待决策事项.md`。

## 3. 模块总览

| 模块 ID | 模块名称 | 一句话范围 | 依赖 |
|---|---|---|---|
| M1 | 输入表单 | 贷款金额/利率/期限字段渲染与默认值 | 无 |

## 4. 功能需求

### 4.1 M1 输入表单

**功能描述**

渲染贷款计算器唯一页面的输入表单区域，包含贷款金额、年利率、贷款期限三组输入字段，以及计算方式切换控件的初始展示。本模块只负责渲染、绑定值与保留用户输入；不做数值校验（见 M2），不做计算方式切换的交互逻辑（见 M4）。

**页面与交互**

- 唯一入口：应用主页面（单页应用，无导航、无其他页面）。
- 首次打开/刷新后的初始状态：
  - 贷款金额（Loan Amount）：空，无默认值。
  - 年利率（Annual Interest Rate）：预填 `4`，单位 %，可修改。
  - 贷款期限 — 年（Years）：空；月（Months，可选补充）：默认 `0`。
  - 计算方式切换控件（Fixed Interest / Reducing Balance）：可见，初始选中「固定利率法（Fixed Interest）」（见 DEC-01，Deferred by user）。
- 所有字段为受控输入，用户可随时修改；修改结果仅保存在页面内存（浏览器会话）中。

**业务规则**

- BR-M1-01：年利率字段默认值为 `4`（表示 4%），用户可修改为任意数值；具体合法性边界由 M2 定义。
- BR-M1-02：贷款期限「年」为主字段，「月」为可选补充字段，未填时视为 `0`。
- BR-M1-03：M1 不做输入合法性校验，仅负责字段渲染、双向绑定与保留当前输入状态。

**数据模型**（对应冻结定型稿 `CalculationInput` 中与表单直接相关的字段）

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| loanAmount | number | 空 | 贷款金额，MYR |
| annualInterestRate | number | 4 | 年利率（%） |
| tenureYears | number | 空 | 贷款期限（年） |
| tenureMonths | number | 0 | 贷款期限补充（月），可选 |
| method | enum(fixed \| reducing_balance) | fixed（见 DEC-01） | 计算方式，供 M3/M4 使用 |

**异常处理/边界情况**

- 本模块不产生错误提示（见 M2）。用户清空必填字段（金额、期限-年）后仍可继续编辑，不阻塞输入本身，也不触发计算。

**验收标准**

- AC-M1-01：首次打开页面时，金额与期限（年）字段为空，年利率显示 `4`，期限（月）字段值为 `0`。
- AC-M1-02：用户在任一字段输入数值后切换焦点或滚动页面，输入值保持不变（不刷新/关闭浏览器的前提下）。
- AC-M1-03：刷新或重新打开页面后，所有字段恢复本节所述初始默认状态（呼应全局约束：无持久化）。

### 4.2 M2 输入校验

**功能描述**

对 M1 中录入的贷款金额、年利率、贷款期限（年/月）进行合法性校验，校验失败时在对应字段显示行内错误提示并阻止触发计算；校验通过后放行给 M3 计算引擎。

**页面与交互**

- 校验触发时机：字段值发生变化即实时校验（假设无独立「计算」提交按钮，见 `待决策事项.md` DEC-03）。
- 校验失败时，仅在该字段下方/旁侧显示对应错误文案，输入框标记为错误态；其他字段不受影响，仍可正常编辑。
- 只要任一字段处于错误态，整体视为「未通过」，不触发 M3 计算；若此前已展示结果，按 DEC-04 处理（见下）。
- 全部字段校验通过后，自动触发 M3 计算并展示结果（M5/M6），无需额外确认操作。

**业务规则**

- BR-M2-01：贷款金额、年利率、贷款期限（年）、贷款期限（月）均不允许为负数（< 0 视为无效）。来源：冻结定型稿已确认决策 N5。
- BR-M2-02（见 DEC-02，Deferred by user）：贷款金额必须大于 0；贷款期限（年 + 月）之和必须大于 0。
- BR-M2-03（见 DEC-03，Deferred by user）：字段变化即触发校验与计算，不设单独提交按钮。
- BR-M2-04：任一字段的错误提示只影响该字段自身的展示，不阻塞其他字段的输入。
- BR-M2-05（见 DEC-04，Deferred by user）：当已通过校验的状态变为校验失败时，隐藏/清空当前展示的结果摘要（M5）与摊还明细表（M6），直至重新校验通过。

**数据模型**

| 字段 | 类型 | 说明 |
|---|---|---|
| fieldErrors.loanAmount | string \| null | 贷款金额字段错误文案，无错误时为 `null` |
| fieldErrors.annualInterestRate | string \| null | 年利率字段错误文案 |
| fieldErrors.tenureYears | string \| null | 期限（年）字段错误文案 |
| fieldErrors.tenureMonths | string \| null | 期限（月）字段错误文案 |
| isValid | boolean | 全部字段是否校验通过，决定是否触发 M3 计算 |

参考错误文案（英文界面）：
- 金额为负：`Loan amount cannot be negative.`
- 金额为 0：`Loan amount must be greater than 0.`
- 利率为负：`Interest rate cannot be negative.`
- 期限（年/月）为负：`Tenure cannot be negative.`
- 总期限为 0：`Loan tenure must be greater than 0.`

**异常处理/边界情况**

- 非数字字符输入：输入框本身限制为数字输入类型，非数字字符无法输入，故校验范围只覆盖数值层面的负数/零判断，不单独处理非数字字符异常（见 DEC-05，Deferred by user）。

**验收标准**

- AC-M2-01：贷款金额输入负数时，该字段下方显示对应错误提示，且不触发计算（结果区域按 BR-M2-05 隐藏/清空）。
- AC-M2-02：年利率输入负数时，行为同上，错误提示对应年利率字段。
- AC-M2-03：贷款期限（年）或（月）输入负数时，行为同上，错误提示对应期限字段。
- AC-M2-04：所有字段均满足 BR-M2-01 与 BR-M2-02（非负、金额 > 0、总期限 > 0）时，校验通过，自动触发 M3 计算并展示结果。
- AC-M2-05：用户将某个已通过校验的字段改为非法值时，结果摘要与摊还明细表按 BR-M2-05 隐藏/清空，直至重新校验通过。

### 4.3 M3 计算引擎

**功能描述**

根据 M1 提供的输入（已通过 M2 校验）和 M4 当前选中的计算方式，计算月供、总利息、总还款额，以及逐期摊还明细（本金部分/利息部分/剩余本金）。计算结果同时供 M5（摘要展示）与 M6（明细表）使用。

**输入**

- `loanAmount`、`annualInterestRate`、`tenureYears`、`tenureMonths`（来自 M1，已通过 M2 校验）
- `method`：`fixed` 或 `reducing_balance`（来自 M4 当前选中状态）

**业务规则 — 通用**

- BR-M3-01：总期数 `numberOfMonths = tenureYears × 12 + tenureMonths`。
- BR-M3-02（见 DEC-06，Deferred by user）：内部计算使用完整精度、不做中间取整；仅对最终展示值（月供、总利息、总还款额、每期本金部分/利息部分/剩余本金）做 2 位小数向上取整（round up），避免逐期累积误差被放大。
- BR-M3-03（见 DEC-07，Deferred by user）：由于展示层取整可能造成累计本金与贷款金额出现尾差，摊还表最后一期的本金部分 = 贷款金额 − 前 (numberOfMonths − 1) 期本金部分展示值之和，确保最后一期剩余本金精确为 `0.00`。

**业务规则 — 固定利率法（Fixed Interest）**

- `totalInterest = loanAmount × (annualInterestRate / 100) × (numberOfMonths / 12)`
- `totalRepayment = loanAmount + totalInterest`
- `monthlyPayment = totalRepayment / numberOfMonths`
- 每期本金部分 `= loanAmount / numberOfMonths`（各期相等，末期按 BR-M3-03 收口）。
- 每期利息部分 `= totalInterest / numberOfMonths`（各期相等）。
- 第 k 期结束后剩余本金 `= loanAmount − (每期本金部分 × k)`，随 k 递增线性递减，第 `numberOfMonths` 期后为 0。

**业务规则 — 递减余额法（Reducing Balance / Amortizing）**

- `monthlyRate = (annualInterestRate / 100) / 12`
- 若 `monthlyRate > 0`：`monthlyPayment = loanAmount × monthlyRate × (1 + monthlyRate)^numberOfMonths / ((1 + monthlyRate)^numberOfMonths − 1)`
- 若 `monthlyRate = 0`（见 DEC-08，Deferred by user）：`monthlyPayment = loanAmount / numberOfMonths`
- 第 k 期（期初剩余本金为 `balance_{k-1}`，`balance_0 = loanAmount`）：
  - `interestPortion_k = balance_{k-1} × monthlyRate`
  - `principalPortion_k = monthlyPayment − interestPortion_k`
  - `balance_k = balance_{k-1} − principalPortion_k`
- `totalInterest = Σ interestPortion_k`（对全部期数求和）；`totalRepayment = loanAmount + totalInterest`。

**数据模型**（对应冻结定型稿 `CalculationResult`）

| 字段 | 类型 | 说明 |
|---|---|---|
| monthlyPayment | number | 月供（末期可能与其他期不同，见 BR-M3-03） |
| totalInterest | number | 总利息 |
| totalRepayment | number | 总还款额 |
| schedule | Array<{periodNumber, payment, principalPortion, interestPortion, remainingBalance}> | 逐期摊还明细 |

**异常处理/边界情况**

- 年利率为 0：递减余额法标准公式分母为 0，需按 BR-M3-03/DEC-08 的推荐处理方式单独计算，避免除以 0。
- 总期数为 1：两种方法均应自然退化为「单期还清本金+当期全部利息」，属于通用公式的自然特例，不需要额外规则。

**验收标准**

- AC-M3-01：固定利率法下，贷款金额 10,000、年利率 4%、期限 1 年（12 期），`totalInterest = 10,000 × 0.04 × 1 = 400`，`monthlyPayment = 10,400 / 12 ≈ 866.67`（2 位小数向上取整）。
- AC-M3-02：固定利率法下，除末期外，每期本金部分与利息部分应分别保持一致。
- AC-M3-03：递减余额法下，利息部分应逐期递减、本金部分应逐期递增，两者之和恒等于当期月供（末期按 BR-M3-03 收口）。
- AC-M3-04：递减余额法下，年利率为 0 时，`monthlyPayment = loanAmount / numberOfMonths`，且每期 `interestPortion = 0`。
- AC-M3-05：任一计算方式下，摊还表最后一期结束后 `remainingBalance` 精确为 `0.00`。
- AC-M3-06：所有展示数值精度为 2 位小数，舍入方向为向上取整（如 `866.661` → `866.67`）。

### 4.4 M4 计算方式切换

**功能描述**

用户在「固定利率法」与「递减余额法」之间手动切换（非并排对比）。切换时保留 M1 中已输入的贷款金额/年利率/期限数值，仅改变计算方式，并按新方式重新触发 M3 计算，刷新 M5/M6 展示的结果。

**页面与交互**

- 切换控件位于表单区（M1 中渲染，见 4.1），呈现为二选一的控件（如 Tab 或 Toggle：`Fixed Interest` / `Reducing Balance`）。
- 用户点击切换后，`method` 状态立即更新；`loanAmount`、`annualInterestRate`、`tenureYears`、`tenureMonths` 的当前值不受影响、不被清空。
- 若切换时当前输入已通过 M2 校验：立即按新 `method` 重新调用 M3 计算，M5（结果摘要）与 M6（摊还明细表）同步刷新为新方式下的结果。
- 若切换时当前输入未通过 M2 校验（处于错误态）：保持原有错误提示，不触发计算，结果区域维持隐藏/清空状态（沿用 BR-M2-05），直至用户修正输入。
- 两种方式的结果不并排展示；切换后，新方式的结果直接替换原方式的结果区域内容，不保留切换前的展示。

**业务规则**

- BR-M4-01：切换计算方式只改变 `method` 字段的值，不影响 `loanAmount`、`annualInterestRate`、`tenureYears`、`tenureMonths` 的当前输入值。
- BR-M4-02：只要当前输入处于校验通过状态，切换后立即使用与切换前完全相同的输入值重新计算，仅计算方式发生变化。
- BR-M4-03：结果展示不做「固定利率法 vs 递减余额法」并排对比；同一时刻只展示当前选中方式的结果。来源：冻结定型稿已确认决策。
- BR-M4-04：页面首次打开时默认选中「固定利率法」。来源：`待决策事项.md` DEC-01（Deferred by user）。

**数据模型**

| 字段 | 类型 | 说明 |
|---|---|---|
| method | enum(`fixed` \| `reducing_balance`) | 当前选中的计算方式，单一状态，无历史记录 |

**异常处理/边界情况**

- 切换发生时若输入未通过校验，不触发计算，也不因切换动作单独产生新的错误提示（错误提示仍来自 M2 对当前字段值的判断）。

**验收标准**

- AC-M4-01：页面首次打开时，默认选中「固定利率法」（对应 BR-M4-04）。
- AC-M4-02：输入合法数值后，切换到另一计算方式：金额/利率/期限字段值不变，结果摘要与摊还明细表按新方式重新计算并展示。
- AC-M4-03：当前字段处于错误态时切换计算方式：切换后仍保持原有错误提示，不触发计算。
- AC-M4-04：任意时刻，页面只展示当前选中方式对应的一组结果，不出现两种方式结果同时并排展示的情况。

### 4.5 M5 结果摘要展示

**功能描述**

展示 M3 计算引擎输出的月供、总利息、总还款额三项汇总数值。仅在输入通过 M2 校验后展示，随输入变化或 M4 切换计算方式实时刷新。

**页面与交互**

- 展示位置：主界面结果区（表单下方或旁侧）。
- 展示字段：`Monthly Payment`、`Total Interest`、`Total Repayment`，均为 MYR 金额，格式遵循 BR-M3-02（2 位小数、向上取整）。
- 显示状态：
  - 输入未通过 M2 校验时，本区域整体隐藏（沿用 BR-M2-05），不展示占位符或 0 值。
  - 输入通过校验后自动展示；输入值变化或通过 M4 切换计算方式后，随 M3 重新计算结果同步刷新，无需用户额外操作。
- 摘要区域标注当前选中的计算方式名称（如 `Fixed Interest` / `Reducing Balance`），避免用户在切换后混淆当前结果对应的算法（见 DEC-09，Deferred by user）。

**业务规则**

- BR-M5-01：三项摘要字段直接取自 M3 输出的 `CalculationResult`（`monthlyPayment`、`totalInterest`、`totalRepayment`），不做额外计算或二次处理。
- BR-M5-02（见 DEC-09，Deferred by user）：摘要区域展示当前选中的计算方式名称。
- BR-M5-03：数值格式化规则遵循 BR-M3-02（2 位小数、向上取整），货币单位标注为 MYR。

**数据模型**

直接消费 M3 的 `CalculationResult.monthlyPayment` / `.totalInterest` / `.totalRepayment`，本模块不新增字段。

**异常处理/边界情况**

- 校验未通过时，本区域完全隐藏，不展示任何占位符、空值或 0 值，避免用户误认为「贷款金额为 0」是有效计算结果。

**验收标准**

- AC-M5-01：输入通过校验后，摘要区域展示 `Monthly Payment`、`Total Interest`、`Total Repayment` 三项，数值为 2 位小数、向上取整、标注 MYR。
- AC-M5-02：输入未通过校验时，摘要区域完全隐藏。
- AC-M5-03：摘要区域标注当前选中的计算方式名称。

### 4.6 M6 摊还明细表

**功能描述**

展示 M3 计算引擎输出的逐期摊还明细：期数、月供、本金部分、利息部分、剩余本金。显隐逻辑与 M5 一致，仅在输入通过 M2 校验后展示，随输入变化或 M4 切换计算方式实时刷新。

**页面与交互**

- 展示位置：主界面结果区，位于结果摘要（M5）下方。
- 表格列：`Period`（期数）、`Payment`（月供）、`Principal`（本金部分）、`Interest`（利息部分）、`Remaining Balance`（剩余本金）。
- 行数 = `numberOfMonths`（总期数），按第 1 期到最后一期顺序列出，与 M3 输出的 `schedule` 数组一一对应。
- 显示状态：与 M5 相同（沿用 BR-M2-05）——输入未通过校验时表格整体隐藏；通过校验后展示，并随重新计算的结果同步刷新。
- 期数较多（如 30 年期 = 360 行）时，MVP 阶段直接一次性渲染全部行，不做分页或虚拟滚动（见 DEC-10，Deferred by user）。

**业务规则**

- BR-M6-01：表格行数 = `numberOfMonths`，与 M3 `CalculationResult.schedule` 数组逐项对应。
- BR-M6-02：表格内数值格式化遵循 BR-M3-02（2 位小数、向上取整）。
- BR-M6-03：最后一行（末期）的本金部分与剩余本金遵循 BR-M3-03 收口规则，剩余本金精确显示为 `0.00`。
- BR-M6-04（见 DEC-10，Deferred by user）：全部期数一次性渲染，不做分页/虚拟滚动。

**数据模型**

直接消费 M3 `CalculationResult.schedule` 数组中的 `periodNumber`、`payment`、`principalPortion`、`interestPortion`、`remainingBalance`，本模块不新增字段。

**异常处理/边界情况**

- 校验未通过时，表格整体隐藏（同 M5）。
- 总期数为 1 时，表格只有一行；该行需同时满足首期与末期的规则——本金部分等于全部贷款金额，剩余本金精确为 `0.00`（BR-M3-03 收口规则在单期场景下的自然结果）。

**验收标准**

- AC-M6-01：输入通过校验后，表格展示 `numberOfMonths` 行，列为 `Period` / `Payment` / `Principal` / `Interest` / `Remaining Balance`。
- AC-M6-02：输入未通过校验时，表格整体隐藏。
- AC-M6-03：最后一行 `Remaining Balance` 精确显示为 `0.00`。
- AC-M6-04：切换计算方式或修改输入后，表格内容按新计算结果同步刷新。

## 5. 非功能要求

### 5.1 性能

- 纯前端计算，无网络请求依赖；输入变化或切换计算方式后，应在用户可感知的短延迟内（建议 < 100ms）完成重新计算并刷新页面展示。
- 页面为静态资源（HTML/CSS/JS），托管于 GitHub Pages，不存在后端接口响应耗时。

### 5.2 兼容性（见 DEC-11，Deferred by user）

支持主流浏览器最新两个大版本：Chrome、Firefox、Safari、Edge。不承诺旧版浏览器（如 IE）的兼容性。

### 5.3 响应式布局（见 DEC-12，Deferred by user）

产品面向通用大众，建议支持移动端与平板浏览器的响应式布局；摊还明细表（M6）在小屏幕下允许横向滚动，保证核心信息可读。

### 5.4 安全与隐私

无账号体系、无后端服务、无数据持久化；所有输入与计算结果仅存于当前浏览器会话内存中，关闭/刷新后清空。不涉及服务端数据安全或用户隐私存储问题。

### 5.5 可用性与托管

静态站点托管于 GitHub Pages，可用性依赖 GitHub Pages 服务本身；MVP 阶段不设自建监控或 SLA 承诺。
